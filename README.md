# 24의 약수 찾기

초등학교 6학년 약수와 배수 복습용 형성평가입니다. 한 문제씩 풀고 해설을 확인한 뒤 다음 문제로 넘어갑니다.

- **체험 주소**: (리포를 만든 뒤 https://<사용자명>.github.io/<저장소명>/ 형태로 바꿔 적으세요)
- **대상**: 초등학교 6학년 · 수와 연산 (약수와 배수)
- **학습목표**: 어떤 수가 24의 약수인지 판단하고, 약수와 배수를 혼동하지 않고 구별할 수 있다.
- **만든 날**: 2026-08-13 · 2026 에듀플러스위크 미래교육박람회 · 서울시교육청 수학 부스
- **만든 이**: 2026 에듀플러스위크 미래교육박람회에서 제작

## 오늘 함께 쓴 기획 카드

**① 맥락과 목적** — 나는 초등학교 6학년 담임 교사이고, 5학년에서 배운 약수 개념을 6학년 복습 차시에 되살리려 한다. 어떤 수가 24의 약수인지를 망설임 없이 판단하게 만드는 것이 목적이다.

**② 작동** — 문항이 한 개씩 나온다. 학생이 답을 고르면 곧바로 맞았는지 표시되고 해설이 뜬다. 학생이 [다음 문제] 버튼을 눌러야 다음으로 넘어간다. 마지막에 [결과 보기]를 누르면 점수와 틀린 문제 다시보기가 나오고, 여러 번 풀면 지금까지 푼 횟수와 최고 점수도 함께 표시된다.

**③ 형태** — 세로 화면(휴대폰) 기준. 위쪽에 진행 막대, 가운데 문제 카드 하나, 아래에 보기 버튼. 문항 8개, 초록 계열 테마, 이모지는 최소한으로.

**④ 협업** — "바로 구현하지 말고 나와 함께 기획하면서 만들어 줘. 내가 꼭 고려해야 하는 것과
고려하면 좋은 것들을 자세하게 제안해 주고, 결정할 것은 최대 5개까지 물어봐 줘.
답을 받으면 완전한 index.html 코드를 한 번에 출력해 줘."

### 아이디어 점검 — 3가지 질문

- **종이보다 나은가?** — 한 문제마다 즉각 채점되고, 고른 보기마다 다른 해설이 나온다. 학습지는 다 풀어야 채점되지만 여기서는 틀린 순간 바로 짚어 준다. 몇 번이든 다시 풀 수 있다.
- **학습이 일어나는가?** — 학생이 24를 나누어 보고 판단한 뒤, 자기가 고른 오답에 맞춘 설명을 즉시 읽고 다음 문항으로 넘어간다.
- **알맹이가 있는가?** — 목표 개념은 약수의 정의(나누어떨어짐). 특히 "배수를 약수로 착각(48·36)", "자기 자신도 약수임을 놓침(24)", "비슷하게 생겨서 약수일 것 같은 수(16)" 세 가지 오개념을 정면으로 겨냥했다.

## 오늘 만든 내용 전체

다른 단원으로 새로 만드실 때 이 부분을 그대로 옮겨 쓰시면 됩니다.

1. (객관식) 다음 중 24의 약수가 아닌 것은? — 보기: 4 / 8 / 16 / 12 — **정답: 16**
   - 해설: 24 ÷ 16 = 1.5로 나누어떨어지지 않아요. 2, 4, 8이 모두 약수라서 16도 될 것 같지만, 24 안에 16이 딱 들어가지 못합니다.
   - 오답별 안내: 4 → "24 ÷ 4 = 6으로 딱 나누어떨어져요" / 8 → "24 ÷ 8 = 3" / 12 → "24 ÷ 12 = 2"

2. (OX) 1은 24의 약수이다. — **정답: ○**
   - 해설: 24 ÷ 1 = 24로 나누어떨어집니다. 1은 모든 자연수의 약수예요.

3. (OX) 24는 24의 약수이다. — **정답: ○**
   - 해설: 24 ÷ 24 = 1로 나누어떨어지죠. 어떤 수든 자기 자신은 그 수의 약수입니다. 이 부분을 많이 헷갈려 해요.

4. (OX) 48은 24의 약수이다. — **정답: ✕**
   - 해설: 48은 24의 '배수'예요. 24 × 2 = 48이니까요. 약수는 그 수를 나누어떨어지게 하는 수라서, 절대 원래 수보다 클 수 없습니다.

5. (객관식) 36이 24의 약수가 아닌 까닭으로 알맞은 것은? — **정답: 36이 24보다 커서 24를 나누어떨어지게 할 수 없기 때문에**
   - 나머지 보기: 36이 짝수이기 때문에 / 36이 24의 배수이기 때문에 / 36이 6의 배수이기 때문에
   - 해설: 어떤 수의 약수는 절대 그 수보다 클 수 없어요. 36은 24보다 크니 나누어떨어지게 할 수 없습니다.
   - 오답별 안내: 짝수 → "4도 짝수이지만 24의 약수랍니다" / 24의 배수 → "24의 배수는 24, 48, 72…예요" / 6의 배수 → "12도 6의 배수인데 24의 약수랍니다"

6. (객관식) 24의 약수를 작은 것부터 차례로 늘어놓을 때, 네 번째 수는? — 보기: 3 / 4 / 6 / 8 — **정답: 4**
   - 해설: 24의 약수를 차례로 쓰면 1, 2, 3, 4, 6, 8, 12, 24 — 네 번째는 4입니다.

7. (단답형) 24의 약수는 모두 몇 개일까요? — **정답: 8** (8개, 여덟, 여덟개, 여덟 개도 정답 처리)
   - 해설: 1, 2, 3, 4, 6, 8, 12, 24 — 모두 8개입니다.

8. (단답형) 24와 36의 공약수 중 가장 큰 수는? — **정답: 12**
   - 해설: 24의 약수는 1, 2, 3, 4, 6, 8, 12, 24이고 36의 약수는 1, 2, 3, 4, 6, 9, 12, 18, 36이에요. 공통으로 들어 있는 수 중 가장 큰 것은 12입니다.

**추가한 기능**: 결과 화면의 「내 기록」 — 지금까지 푼 횟수, 최고 점수, 최근 5회 기록이 표시됩니다. 첫 판에는 보이지 않고 두 번째부터 나타나며, 기록은 그 기기(그 태블릿·그 폰)에만 저장됩니다.

## 1. 오늘 만든 걸 고치고 싶다면

문항을 바꾸거나 색을 바꾸는 등 **오늘 작품을 손보는 방법**입니다. 코드를 몰라도 됩니다.

1. 이 저장소에서 **`index.html`** 파일을 클릭합니다.
2. 오른쪽 위 **복사 버튼**(📋 모양)을 눌러 코드 전체를 복사합니다.
3. **Claude / ChatGPT / Gemini** 중 아무 곳이나 새 대화를 열고, 복사한 코드를
   **한 번에 붙여넣은 뒤** 이렇게 보냅니다.

   > "이 콘텐츠 수정할 거야. 먼저 코드를 파악해 줘."

4. AI가 파악을 마치면, 고치고 싶은 것을 **하나씩** 말합니다.

   > "3번 문항을 ○○ 내용으로 바꿔 줘"
   > "문항을 5개 더 추가해 줘"
   > "색을 초록색 계열로 바꿔 줘"

5. 마음에 들면 **완성된 코드 전체를 복사**합니다.
6. 다시 이 저장소의 **`index.html`** 을 열고 오른쪽 위 **연필 모양(✏️) 버튼**을 누릅니다.
7. **기존 내용을 전부 지우고**(Ctrl+A → Delete) 복사한 코드를 붙여넣습니다.
8. 아래 **Commit changes** 버튼을 누르면 끝입니다.

1분쯤 뒤 원래 주소를 새로고침하면 바뀐 내용이 보입니다.
**주소는 그대로**이므로 학생들에게 이미 알려준 주소를 다시 알려줄 필요가 없습니다.

> 파일 이름은 반드시 **`index.html`** 이어야 합니다. 이름이 다르면 페이지가 열리지 않습니다.

## 2. 새로 만들고 싶다면 — 프롬프트 쓰는 법

다른 단원, 다른 활동을 새로 만들 때는 **기획부터** 적으시면 됩니다.
"○○ 만들어 줘" 한 줄로 시키는 것과 결과가 크게 달라집니다.

**① 맥락과 목적** — 나는 누구이고, 무엇을 배우게 하려는가?
> "저는 중학교 2학년 수학 교사입니다. 학생들이 일차함수의 기울기를 연습하면 좋겠어요."

**② 작동** — 어떻게 작동하나? (조작 → 판정 → 피드백 → 종료)
> "문제를 하나씩 보여주고, 답을 고르면 바로 맞았는지 알려주고, 틀리면 왜 틀렸는지 설명해 주세요. 10문제를 다 풀면 점수를 보여주세요."

**③ 형태** — 결과물이 어떻게 생겼나? (화면 구성, 문항 수, 색·이모지)
> "스마트폰 세로 화면에 문제 하나씩 보이게 하고, 파란색 계열로 깔끔하게 만들어 주세요."

**④ 협업** — 여기가 가장 중요합니다. **"구현해 줘"가 아니라 "함께 기획하자"** 라고 하세요.
아래 문장을 그대로 복사해서 마지막에 붙이세요.

> "바로 구현하지 말고 나와 함께 기획하면서 만들어 줘. 내가 꼭 고려해야 하는 것과
> 고려하면 좋은 것들을 자세하게 제안해 주고, 결정할 것은 최대 5개까지 물어봐 줘.
> 답을 받으면 완전한 index.html 코드를 한 번에 출력해 줘."

이 한 문장 때문에 AI가 **되묻습니다.** 그 질문에 답하는 과정이 곧 기획이고,
결과물의 질을 좌우합니다. **기획이 90%입니다.**

### 그대로 복사해서 쓰는 틀

```
[맥락과 목적] 나는 누구이고, 무엇을 배우게 하려는가

[작동] 조작 → 판정 → 피드백 → 종료 흐름

[형태] 화면 구성, 문항 수, 색·이모지

[협업] 바로 구현하지 말고 나와 함께 기획하면서 만들어 줘. 내가 꼭 고려해야 하는 것과
고려하면 좋은 것들을 자세하게 제안해 주고, 결정할 것은 최대 5개까지 물어봐 줘.
답을 받으면 완전한 index.html 코드를 한 번에 출력해 줘.

[기술 제약]
- 파일 하나(index.html)로만, CSS·JS는 파일 안에 인라인
- 외부에서 아무것도 불러오지 않기(인터넷 요청 0)
- 스마트폰 세로 화면 우선, 버튼은 손가락으로 누르기 편한 크기
```

문항 내용까지 정해 두셨다면 위 틀 아래에 **문항·정답·해설을 그대로 적어** 보내시면 됩니다.
(이 문서 위쪽 「오늘 만든 내용 전체」가 그 예시입니다.)

### 만들기 전 스스로 점검하는 3가지 질문

- **종이보다 나은가?** — 즉각 피드백 / 랜덤화·무한 재도전 / 시간 압박 / 시뮬레이션 /
  개별화 중 **근거가 하나는** 있어야 합니다. "화려해서"는 근거가 아닙니다.
- **학습이 일어나는가?** — 학습자가 무엇을 하고, 어떤 피드백을 받나요?
- **알맹이가 있는가?** — 목표 개념, 또는 겨냥하는 대표 오개념이 무엇인가요?

## 3. 새로 만든 걸 인터넷에 올리려면

새로 만든 작품은 **저장소를 하나 더 만들어서** 올립니다. (오늘 저장소에 덮어쓰면
오늘 작품이 사라집니다.)

1. github.com 오른쪽 위 **+ → New repository**
2. 저장소 이름을 영문으로 간단히 적고 **Public** 선택 → **Create repository**
3. AI에게 받은 코드를 저장할 때 **파일 이름을 `index.html` 로** 바꿉니다.
4. 저장소 화면에서 **Add file → Upload files** → `index.html` 을 끌어다 놓기 →
   아래 **Commit changes**
5. **Settings**(위쪽 톱니바퀴) → 왼쪽 메뉴 **Pages** →
   Branch 항목이 **None** 으로 되어 있는 것을 **main** 으로 바꾸고 → **Save**
6. **약 1분 뒤** 아래 주소에서 열립니다.

```
https://<내 계정 이름>.github.io/<저장소 이름>/
```

> 예를 들어 계정이 `mathteacher`, 저장소가 `slope-quiz` 라면
> `https://mathteacher.github.io/slope-quiz/` 입니다.

바로 안 열려도 당황하지 마세요. 처음 배포는 1~2분 걸릴 수 있습니다.
새로고침을 몇 번 해보시고, 그래도 안 되면 파일 이름이 `index.html` 이 맞는지 확인하세요.

## 4. 막히면 AI에게 물어보세요

```

하나를 만들어 인터넷에 올려 보는 10분짜리 체험을 했습니다.

   - 맥락과 목적: 나는 누구이고 무엇을 배우게 하려는가

- AI에게 받은 코드를 어떻게 고쳐 나가는지, 고친 것을 어떻게 다시 올리는지

- 저를 코딩을 전혀 모르는 교사라고 생각하고 설명해 주세요.
- 전문용어를 쓰실 때는 쓸 때마다 한 줄로 뜻을 풀어 주세요.
- 한 번에 많이 설명하지 말고, 하나씩 물어보며 진행해 주세요.
```
